# Воспроизводитель к находке D1 (MAM, 2026-08-28)

Кладётся в корень клона MAM как `probe/main.go` и гоняется `go run ./probe`.
Собран против `github.com/downstream-protocol/a downstream consumer-Memory-Admissibility-Management-MAM-`,
коммит `9f9b871`, Go 1.22.2.

Что показывает, дословным выводом:

    жизненный цикл НЕ УСТАНОВЛЕН вовсе         -> решение 0  причина USE
    явно активна                               -> решение 0  причина USE
    явно отозвана                              -> решение 4  причина MEMORY_REVOKED
    высшая чувствительность при лимите Tier1   -> решение 0  причина USE

Оба вызова передают маску, в которой вызывающий ТРЕБУЕТ
`RequiredLifecycle = FlagLifecycleActive` и ставит
`SensitivityLimit = Tier1Preference`.

Ни одно из этих двух полей не читается в `EvaluateMemoryHotPath`
(`pkg/evaluate/evaluate.go:40-78`) — проверено чтением тела функции и
командой `grep -rn "RequiredLifecycle\|SensitivityLimit" --include="*.go" .`,
которая находит их только в объявлении структуры, в наряде-харнессе и в
переносе с провода в `pkg/rpc/server.go:42`.

Следствие: «жизненный цикл не установлен» и «жизненный цикл активен»
неразличимы для решателя. Это ровно то различение, которое мы уже
называли в AF-OSE: булев не отличает «не установлено» от «не нарушено».
