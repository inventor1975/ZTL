# store — атом-стор и его корпуса

**Отделено от `introspect/` 2026-08-30 по слову куратора: «стор — это не
интроспект».** Разница по назначению, и она настоящая:

    store       ЗАЗЕМЛЕНИЕ ПОИСКОМ. Ничего не судит. Хранит атомы
                источников, собирает корпуса, отдаёт релевантное.
    introspect  РАЗБОР ТЕКСТА. Метки берутся не по слову человека, а из
                ИСТОЧНИКА; судит при этом ЯДРО, а не он сам.

## Что здесь лежит

    atomstore.py     каталог атомов, зеркалящий дерево источника; корпуса
                     складываются. Команды: atomize / collect / index /
                     query / stats
    stored.py        тёплая служба (`atomstore.service`, юзерский systemd):
                     держит модель в памяти. Холодный запуск был 16,9 с
    chat_to_store.py чат Телеграма -> корпус CHAT; крон, каждый день в 00:00
    py_corpus.py     корпус Python — МАШИННО, без форков и токенов
    lean_corpus.py   корпус Lean — там же, без форков

Данные стора лежат **вне репозитория**, в `ztl-private/atomstore/`.

## ЧЕГО СТОИТ КАКОЙ КОРПУС

`py_corpus` и `lean_corpus` собираются машиной и стоят НОЛЬ. Прозаические
корпуса (`ZTLDOC`, `BOOK`, `LAW`, `DOWNSTREAM`) идут через `atomize` → **форк
извлекает атомы** → `collect` → `index`, и извлечение стоит денег куратора.
Пересобирать прозу — только по его слову.

## ШОВ, КОТОРЫЙ ОСТАЛСЯ И НЕ СПРЯТАН

`atomstore.query` — не чистый ретрив: он заканчивается сверкой ответа
`guard`'ом, который остался в `introspect/`. Значит стор ЗАВИСИТ от
анализатора через один ленивый импорт, и путь к нему прошит явно, с
пометкой в коде. Разрезать ли `query` на ретрив и сверку — не решено;
пока зависимость названа вслух, а не замазана.
