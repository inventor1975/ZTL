# ZNUM — числовой этаж ZTL: семантика на бумаге (черновик, этап 1)

Статус: СЛОВА ДО КОДА. Ни одной строки реализации до «да» куратора по
развилкам §6. Ведущая задача (решение куратора 2026-08-10): **судья
численных клеймов** — числа со знаменателями и провенансом, диспозиции и
носители; материал для катания — наша ежедневная claim-discipline.
Статья («Числа в кредит») — урожай потом; сорит — вопрос статьи, припаркован.

## 1. Что уже дано ядром (не переизобретаем)

§15 препринта: числа с частичным знанием = интервалы в ЛЕНИВОМ регистре
(интервальная арифметика, декоррелированная); сравнения = ЖАДНЫЕ атомы по
порождающему принципу (T если форсировано всеми прочтениями; F если
форсирована ложь; иначе Z). §16: вероятностный этаж (Bel/Pl-пороги). §12:
интервальные мощности. Двухрегистровая теорема (§9) уже покрывает числа:
величины текут, утверждения судятся. ZNUM — не новая логика, а ПОДАТЧИК
АТОМОВ: числовой этаж производит T/F/Z-атомы сравнений, дальше работает
нетронутое ядро (ztljudge/zverify без изменений).

## 2. Объекты

**Числовая величина** (quantity) = тройка:

    (имя, интервал [lo, hi], провенанс)

- интервал — текущее знание о значении; точное значение = [x, x];
  полное незнание = (−∞, +∞) или доменные границы;
- провенанс — статус границ: EARNED (границы предъявлены свидетелем:
  измерение с погрешностью, документ, пересчёт) или CREDIT (границы
  заявлены, но не предъявлены — «голое число»).

**Ключевое отождествление: голое число = число в кредит.** «Выручка
$4.2M» без источника — это [4.2M, 4.2M] с провенансом CREDIT: считать
им можно (ленивый регистр течёт), но любой вердикт, едущий на нём,
не поднимается выше ON CREDIT. Это числовой аналог Z-атома: не «ложь»
и не «истина» — не заработано.

**Числовой атом** (то, что судится) = сравнение над величинами:
`a < b`, `a ≤ b`, `a = b` (в допуске), `a ∈ [c, d]`, `sum(...) ≤ b`.
Вердикт атома — по лифту: T форсировано / F форсировано / иначе Z.

## 3. Лифт для арифметики

Операции (+, −, ×, ÷, min/max, sum) действуют на интервалы образом по
всем прочтениям — интервальная арифметика Мура, в ленивом регистре.
Каждое ВХОЖДЕНИЕ величины читается независимо (декорреляция) — ровно как
в пропозициональном лифте («every occurrence of Z is substituted
independently»): m − m ∈ [lo−hi, hi−lo] ≠ 0. Это честная цена (известная
как dependency problem у интервальщиков); замер её остроты на реальных
сметах — часть этапа 2. Деление на интервал, содержащий 0 → результат
не определён → атом, читающий его, = Z (эхо 1/0 из §25: неденотирующий
терм = метка).

Провенанс течёт по операциям pessimistically: результат EARNED только
если ВСЕ операнды EARNED; одна CREDIT-величина заражает результат
(аналог: одна непроверенная посылка держит вывод в кредите). Пьедигри
(какие именно CREDIT-величины) сохраняется — это будущие carriers.

## 4. Вердикт, грейды, носители

Сравнение даёт T/F/Z-атом → формулы над такими атомами судит
СУЩЕСТВУЮЩИЙ ztljudge (диспозиции EARNED / ON CREDIT / OPEN / REFUTED).
Два источника кредита, и их НЕЛЬЗЯ смешивать:

- **интервальный Z**: перекрытие интервалов — даже идеальные измерения
  не форсируют вердикт; лечится сужением (доп. измерение);
- **провенансный кредит**: вердикт форсирован интервалами, но интервалы
  сами не заработаны; лечится предъявлением свидетеля.

Диспозиция численного клейма = min по обеим осям (двумерная клетка, как
эпистемика×операционалка в §22).

**Верификация** = сужение интервала СО свидетелем (перевод CREDIT→EARNED
и/или shrink). **Expire** (E25) = граница теряет грунт → интервал
расширяется/уходит в CREDIT — эпохи работают без изменений.

**Теорема-ставка этапа 2 (мерить, не верить):** сужение монотонно
(прочтения — подмножество) ⇒ T-форсированный интервальный вердикт не
отзывается никаким дальнейшим сужением ⇒ на чисто числовых атомах
sound=hereditary и грейд считается за ОДИН проход (в пропозициональном
случае это стоило перебора глубины m−1). Известный кандидат-убийца:
коррелированные вхождения при частичном сужении. Если теорема падает —
честно фиксируем контрпример, как «гипотезу, прожившую час» (§21).

**Носители** (carriers) — перенос из E36 дословно: величина несущая,
если её деградация (интервал→полное незнание / EARNED→CREDIT) меняет
диспозицию. what_if для чисел: «какую величину сузить/подтвердить, чтобы
клейм решился» — числовой next_check.

## 5. Судья клеймов: формат листа

    label :: формула-сравнение :: величины

    пример:
    smeta :: sum(line1, line2, line3) <= budget ::
        line1 = [1000, 1000] earned:invoice-17
        line2 = [2000, 2000] earned:invoice-18
        line3 = [500, 3000] credit          # непроверенная строка
        budget = [5000, 5000] earned:order-o4

    вывод судьи:
    ON CREDIT / interval-Z — вердикт зависит от line3;
    next_check: verify line3 (сузить до ≤2000 → EARNED; >2000 → REFUTED)

Знаменатели: «детекция 100%» = claim `detected = attempted` с
attempted как величиной; незаработанный attempted → клейм максимум
ON CREDIT, слабое звено названо. Snapshot-дисциплина: величина несёт
провенанс-реф (коммит/документ) — «цифра без снапшота» ловится как CREDIT.

## 6. РАЗВИЛКИ — нужно «да»/правки куратора ДО кода

- **F1. Декорреляция по вхождениям** (как в ядре; m−m ≠ 0). Альтернатива —
  отслеживать тождество вхождений (точнее, но чужая ядру механика и
  дорого). ПРЕДЛАГАЮ: декорреляция, как §15; остроту мерить.
- **F2. Голое число = [x,x] в кредите** (считать можно, вердикт не выше
  ON CREDIT). Альтернатива — отказ принимать числа без свидетеля вообще
  (жёстче, но лист клеймов из жизни станет неписуемым). ПРЕДЛАГАЮ: кредит.
- **F3. Две оси кредита раздельно** (интервальный Z ≠ провенансный CREDIT,
  обе видимы в выводе). Альтернатива — схлопнуть в один статус (проще
  читать, но теряем «что лечится измерением, а что документом»).
  ПРЕДЛАГАЮ: раздельно — это и есть главная диагностическая ценность.

## 7. Границы юрисдикции (заявляем сразу)

Точное равенство вещественных не зарабатывается (§13) — только допуски.
Вероятностные клеймы — потом, через §16 (Bel/Pl), не в первом ядре.
Размытость (сорит) — вопрос статьи, не реализации; припаркован.
Единицы измерения — вне первого ядра (величины безразмерны либо
согласованы вручную; несогласованность единиц = ошибка формализации,
не вердикт).
